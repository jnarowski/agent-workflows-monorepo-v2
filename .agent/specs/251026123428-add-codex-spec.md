# Feature: Add Codex Agent Support

## What We're Building

Complete integration of OpenAI Codex as a supported agent in the agent-workflows system, including comprehensive type definitions based on actual Codex CLI v0.46.0 event structures, message parsing/transformation, and UI components for rendering Codex messages with tool-specific blocks for shell, apply_patch, and update_plan operations.

## User Story

As a developer using the agent workflows platform
I want to start sessions with OpenAI Codex in addition to Claude
So that I can leverage Codex's capabilities and choose the best agent for different tasks

## Technical Approach

Implement Codex support in three layers:
1. **Type Layer**: Define complete TypeScript types for all Codex event structures (session_meta, response_item, event_msg, turn_context) based on actual mock JSONL files
2. **Transform Layer**: Build message parsing and streaming transforms to convert Codex events into standardized SessionMessage format
3. **UI Layer**: Create Codex-specific message renderer with components for user messages, assistant messages, reasoning blocks, and tool blocks (shell, apply_patch, update_plan)

The implementation leverages existing patterns from Claude integration while respecting Codex's distinct event structure (response_item with payloads vs Claude's direct message events).

## Implementation Plan

### Phase 1: Foundation - Type System

Define complete, accurate TypeScript types for all Codex events based on mock JSONL files. This includes session metadata, response items (messages, reasoning, function calls), event messages (user/agent messages, reasoning, token counts), and turn context. Make ExecutionResponse generic to support adapter-specific event types.

### Phase 2: Core Implementation - Transforms and Parsing

Implement message transformation logic to convert Codex's JSONL event stream into standardized SessionMessage format. Update parsers to use new typed events. Build streaming transforms to handle real-time Codex events from WebSocket.

### Phase 3: Integration - UI Components

Create Codex message rendering components following existing Claude patterns but adapted for Codex's event structure. Build tool-specific renderers for shell, apply_patch, and update_plan based on actual usage in mock files.
